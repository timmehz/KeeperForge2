# Creature type records (creature lists, section 0xAA)

What a creature type is made of in the level files: Creatures.kwd, or a level's own copy of that list. The ids themselves are
in creatures.md. LevelFiles.h (`CreatureOffset`, `CreatureFlag`, `CreatureAttributes`) holds the layout in code.

How this was found: the official editor (pro version) has a "Modify Creature Properties" window. Its controls (from its
dialog resource) were matched to the fields its window code fills, and those to where its file writer puts each field in a
record. Then every place was checked in our export of DKII-DX.exe: the game's own converter 0x568E30 reads each place
listed below [verified]. What each place *means* is the editor's [reference, editor]. Where a value was also checked against
the user's screenshot of the official editor showing Warlock (id 5), it says so [verified: screenshot].

## The list
- A list section: block 0xAB (count at +8), block 0xAC with the records. Creatures.kwd has 46 records of 0x1549 bytes
  [verified by eye].
- The game's reader (0x56A250) has one buffer of 0x1549 bytes for a record. A record of that size is read straight in;
  any other size has the buffer cleared first, then is read in at its own size, so a longer one runs past the buffer
  [verified]. Then 0x568E30 converts the buffer, so nothing past 0x1549 reaches the game. We never make records longer.
- The official editor writes 0x15A1 byte records. Its extra flags live past 0x1549, so this game never sees them:
  Available Via H.Portal, Immune To Lightning, Is Stone Knight, Is Emotionless (a second flags word at +0x1599)
  [verified: reader size; reference: which flags]. Our window leaves them out.
- A type's id is its place in the list from 1, also stored at +0xF4B [verified]. So a type can only be added at the end, and
  deleting one from the middle would renumber every type after it. The editor adds at the end and deletes only the last,
  and only after the shared list's 46.

## A level's own list
- A level's .kwd lists `Data\Editor\Creatures` (type 0xAA) like any other file. One stock level (Furnace_hero) lists
  a `<name>Globals.kld` (type 0) instead: a file holding every shared list, its creature list among them, with records of
  0x15A1 bytes [verified by eye]. So a level can carry its own creature types.
- The game's file loader (0x56C960) uses a listed path with a three-letter extension as it is. A path without one gets
  .kwd tried first, then the other extensions. It then reads every section in the file [verified]. So a level-owned
  `<name>Creatures.kld` holding only section 0xAA, listed under type 0xAA, should load in place of the shared one.
  [unverified in game]
- The editor saves changed creature types that way (level-files.md).

- Effect, object and room ids are their place in Effects.kwd, Objects.kwd and Rooms.kwd from 1 [verified: the Warlock
  values above name its own effects and bed; room ids match rooms.md].
- Attractions: kind 0 none, 1 room, 2 gold, 3 mana, 4 creature. For a room or creature the value's low byte is its id
  and the 16 bits from bit 16 an amount; for gold and mana the value is the amount. The official editor offers only
  "room" for the first [reference, editor]. Warlock: the first is room 6 (Library), the second none [verified: screenshot].
- Art resources: see below.

## Types past the stock 46 [verified in the export unless marked]
A sweep for fixed-size per-type tables, for adding creature types (mods):
- The list reader takes any number of records, and type ids are bytes (so at most 255 types).
- Each player has a portal table of 46 entries of 0x12 bytes at player + 0xB57: { type byte, + 2 "attracted" (set by the
  per-tick pass 0x4DBD90 when the type first qualifies), + 6 a weight multiplier (fixed point, 0x1000 = 1; 0xA000 means
  weight x 200, the first-arrival boost), + 0xE a second multiplier (0xA000 means weight 0, blocked) }. Made by the
  player's constructor with a count of 0x2E, filled by the player's level set-up (0x4B8640) with the world's types at
  places 0-45, saved as "CreatureEntranceInfo" and part of the sync checksum. The per-tick pass took each slot's type
  from the world's list at the slot's place (0x4DBDC7), and the portal's choice (0x4DBF90) looks a type up by its id
  and takes slot 0 when it is not there. So a type past the 46th got slot 0's values: no first-arrival boost and no
  block of its own, otherwise weighted normally.
  Fix (CreatureFixes, written, not tested): after the level set-up, when the world has more than 46 types, the slots
  go to the types that can come through a portal first (keeper Portal flag 0x400 in data + 0x686, then mercenaries,
  data + 0x68A bit 8, then heroes, data + 0x686 bit 0x80 clear, then the rest), and the per-tick pass reads each slot's
  type from the slot. With 46 types or fewer nothing changes. A warning is logged if more than 46 types can come
  through a portal.
- Each player has "CreatureUsed", 47 counters of 4 bytes at player + 0xFCE (cleared, saved and in the checksum). No code
  that counts into it by type was found, so it does not limit new types.
- Loops bounded by 46 elsewhere: only the ones over the portal table (set-up, save, checksum, per-tick pass, choice).
- Other per-type tables in the game's state dump: "CreatureOnLevel" is 256 entries at world + 0x7109 (one per possible
  id); "TorturedCreatureTypeList" is a list head (player + 0x4C), not a bitmask; "CreaturesKilled" is per player (7).
- Our own code: the level editor's creature icon table has 46 cells. Past them, a type a mod made as a copy of a stock
  type shows that type's icon; others show "?".
- Not checked [unverified]: the in-game Creatures panel with many types (its icons come from each type's record) and
  scripts that name types past 46 (they store a type byte, so they should work).

## Art resources
0x54 bytes each [reference, editor: the accessors of its art resource object, which holds the 0x54 bytes after its own
pointer, and its art window]:
- +0 the name (64 characters, a file or sheet name), +0x40 flags, +0x44, +0x48, +0x4C values that go with the type, +0x50
  the type, +0x51 and +0x52 two bytes.
- Types: 0 Null, 1 Sprite, 2 Alpha, 3 Additive Alpha, 4 Terrain Mesh, 5 Mesh, 6 Animating Mesh, 7 Procedural Mesh, 8 Mesh
  Collection. Fields: Sprite, Alpha, Additive Alpha: width +0x44, height +0x48 (fixed), frames +0x4C. Mesh: scale +0x44
  (fixed), frames +0x48. Animating Mesh: frames +0x44, FPS +0x48, start distance +0x4C and end distance +0x4E (16 bit, in
  1/4096ths), start AF +0x51, end AF +0x52 (bytes). Procedural Mesh: an ID at +0x44. The others have none. Choosing Null in
  the official editor clears the whole resource.
- Flags: 1 a resource is there (set for any type but Null), 2 Player Colored (Alpha, Additive Alpha), 4 Animating Texture,
  8 Has Start Animation, 0x10 Has End Animation (Animating Mesh), 0x20 Random Start Frame, 0x40 Origin At Bottom, 0x80
  Doesn't Loop, 0x100 Flat (sprites), 0x200 Doesn't Use Progressive Mesh (meshes), 0x10000 Use Animating Texture For
  Selection, 0x20000 Pre-Load, 0x40000 Blood. [reference, editor: its art window's OK hands each box to its bit]
- Where they are in a creature record: animations 1 to 36 at +0x20 + 0x54 * n (n from 0; place 0 holds no resource in stock
  files), 37 to 41 at +0xFD1, +0x12CF, +0x13E3, +0x1437, +0x148B, 42 to 47 from +0x1083, 0x54 apart. GUI Icon +0xC44,
  Portrait +0xD40, the side panel icon +0xC98 ("CreatureIcons#4" for Warlock), Unique Resource +0x14F1, 1st person Filter
  +0xF77 and Melee +0x1027. [verified: stock file names, such as Warlock-Walk in 1, Warlock-DiePose in 41, the portrait
  "...\warlock-bg"; which button is which, from the official editor's message map] Its Statue Resource button has no handler
  in the version looked at, so its place is not known.
- Animation names by what stock creatures keep in each: 1 Walk, 2 Run, 3 Being Dragged, 4 Recoil Forwards, 5 Melee Attack, 6
  Cast Spell, 7 Die, 8 Happy, 9 Angry, 10 Stunned, 11 In Hand, 12 Sleeping, 13 Eating, 14 Researching, 17 Tortured, 19
  Drinking, 20 Idle 1, 21 Recoil Backwards, 22 Manufacturing, 23 Praying, 24 Fall Back, 25 Electrocuted (pose), 26
  Electrocuted, 27 Get Up, 28 Dance, 29 Drunk (heroes'), 30 Entrance, 31 Idle 2, 32 to 33 and 35 special ones (bat, whip,
  eat corpse, loot ...), 34 Drunk, 37 Drunken Idle, 38 Back Off, 39 Pose Frame, 40 Stealth Walk, 41 Death Pose, 42 Melee 2,
  43 to 47 extra ones (Imp's idles and second dig). 15, 16, 18 and 36 hold nothing in any stock creature. [verified: stock
  file names; the official editor's own names for its buttons do not all match these one for one]
- Footstep frames: a left and a right 16 bit frame for each animation, at +0x1323 + 4 * animation. [reference, editor]

## The official editor's other windows
These come from its file reader, which reads each part of a record at the place below and hands it to the window that edits
it [reference, editor]. Where stock data was checked, it says so.
- String / Text IDs (16 bit): ToolTip +0xF26, Name +0xF24, General Description +0xF38, Strength +0xF3A, Weakness +0xF3C,
  Introduction +0xCFF. The name's place agrees with what the lobby reads (creatures.md) [verified]; the three descriptions
  are in the order the window sets them [reference, editor].
- Job preferences: Happy three at +0xE14, Unhappy two at +0xE38, Angry three at +0xE50, each 12 bytes: 32 bit job, 16 bit
  mood change, 16 bit mana change, byte chance (0 to 100), then three bytes of padding (0xCD in stock files). Hated jobs: four
  32 bit jobs at +0xE74. Alternatives: three of 8 bytes at +0xE7C: job, mood change, mana change. Mood and mana go from -10000
  to 10000 in the official editor. Jobs: 1 Sleep, 2 Eat, 3 Research, 4 Train, 5 Manufacture, 6 Guard, 7 Torture, 8 Pray,
  9 Drink, 10 Leave, 11 Destroy Rooms, 12 Destroy Walls, 13 Steal Gold, 14 Steal Spells, 15 Sulk, 16 Rebel, 17 Steal
  Manufacture Crates, 18 Kill Creatures, 19 Kill Player, 20 Tunnelling, 22 Wait, 23 Send To Action Point, 24 Explore, 25
  Steal Enemy Gold, 26 Combat Pit Spectate, 27 Jail Break, 28 Tolling. [verified: Warlock is happy to Research (80%), Train
  and Pray, and hates Manufacture]
- Available attacks: three of 0x18 bytes at +0xDC4: shot offset X, Y, Z (fixed), +0xC a byte the editor always writes 0,
  +0xD play animation (0 or 1), +0x10 shot delay (fixed, seconds), +0x16 the spell (CreatureSpells.kwd by place from 1), +0x17
  the level it comes at. [verified: Warlock's are Warlock Fireball at 1, Warlock Heal Creature at 2, Warlock Firebomb at 8,
  each 2.77 s] Melee: attack +0xF50 (byte; which list it names depends on flag bit 11, not decoded), recharge time +0xEF8 and
  range +0xEEC (fixed), damage +0xF14 (16 bit), shot delay +0xCF9 (fixed), play animation flag bit 29.
- Resistances: four of { type, percent 0 to 100 } at +0xE0C. Types: 1 Melee Blade, 2 Melee Blunt, 3 Melee Body, 4 Fire,
  5 Movement, 6 Lightning, 7 Gas, 8 Projectile, 9 Enhance Other, 10 Enhance Self, 11 Close Combat, 12 Generation, 13 Physical
  Trap, 14 Non-Lethal Trap, 15 Melee Scythe. [verified: Bile Demon has Gas 100] Salamander has a type 16 the editor does not
  name.
- Light, 24 bytes at +0xD94: X, Y, Z, radius (fixed), 32 bit flags at +0xDA4, red, green, blue bytes at +0xDA8. Flags: 2
  Flicker, 4 Pulse, 0x80 Player Colored (in the window's order), and 0x800, 0x1000, 0x2000 add 256 to red, green, blue, so a
  color goes to 511. [verified: Firefly's is radius 1.5, red 460, green 500, blue 10]
- Anger string IDs (16 bit): Lair, Food, Pay, Work, Slap, Held, Lonely, Hatred, Tortured at +0xD05 on, two apart; General at
  +0xCF7.
- 1st person: special abilities at +0xF46 and +0xF47 (byte: 0 None, 1 Pick Up Workers, 2 Sniper Mode, 3 Turn To Bat, 4 Fly,
  5 Hypnotise, 6 Disguise / Steal, 7 Pray, 8 Pick Locks, 9 Fear Attack, 10 Ghost Possession), each with a 32 bit value at
  +0x14E9 and +0x14ED (which value goes with which ability is from where the boxes sit in the window). Swipes (byte, 0 Null
  to 22): Melee 1 +0xF42, Melee 2 +0xF43, Special 1 +0x1025, Special 2 +0x1026, Spell +0xF45 [verified: Warlock's Melee 1
  is Staff Strike]. Gamma effect +0xD3C (0 Normal to 16 Ghost). Waddle scale +0xDBC, oscillate scale +0xDC0 (fixed), walk
  cycle +0xD45 (byte), camera rolls when turning: flag bit 28.
- Animation offsets: eight of X, Y, Z (32 bit): Portal Entrance at +0xE94, the other seven (Praying, Fall Back / Get Up,
  Corpse, Offsets 5 to 8) from +0x127B, 12 apart. [unverified: that they are 1/4096ths like the record's other places; our
  window shows them that way]
